# DECISIONS.md

## 1. Какие платежи считать выплаченными
**Решение:** учитывать только `paid` с `paid_at`, не превышающим дату отчёта.

**Варианты:** использовать `created_at`, учитывать `queued` или `refunded`.

**Почему:** нужен фактически выплаченный на дату отчёта объём. `queued` ещё не ушёл, `refunded` был возвращён.

**Если неверно:** изменятся выплаченная и оставшаяся суммы.

## 2. Как распределять платежи без `work_id`
**Решение:** сначала учесть явно привязанные платежи. Непривязанные распределять внутри договора: сначала `done` по `completed_at`, затем `planned`, затем `cancelled`; при равенстве — по `work_id`.

**Варианты:** пропорционально ценам; распределять только на уровне договора; использовать другую дату.

**Почему:** точной связи в данных нет. Выбранное правило детерминировано и сначала закрывает уже принятые работы.

**Если неверно:** изменится распределение по работам, но не общая сумма платежей договора.

## 3. Отменённая работа
**Решение:** не удалять её из отчёта; сохранить цену, фактические выплаты и арифметический остаток, показывая `cancelled`.

**Почему:** формат содержит цену, но не содержит правила, уменьшается ли сумма договора после отмены. Поэтому программа не придумывает такое списание.

**Если неверно:** нужно будет подтвердить правило компании и пересчитать остаток.

## 4. Денежная точность
**Решение:** `Decimal`, 2 знака после запятой.

**Почему:** задание требует точности до копейки; `float` для денег не используется.

**Если неверно:** потребуется изменить только денежный тип/округление.

## 5. Дата отчёта
**Решение:** используется `paid_at <= report_date`, а не `created_at`.

**Почему:** вопрос сформулирован как «сколько уже выплачено на дату».

**Если неверно:** платежи, заведённые до даты, но оплаченные позже, ошибочно попадут в отчёт.
